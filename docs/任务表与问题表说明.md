# 任务表与问题表分别记录什么？

## 一句话理解

- **任务表：计划要做的工作及当前状态**，回答“谁在什么时候交付什么，怎样算完成”。
- **问题表：执行中出现的偏差、缺陷或阻塞**，回答“哪里出了问题，谁处理，修复后谁验证”。

例如，“完成路网可视化原型”是任务；“原型筛选条件与需求不一致”是该任务关联的问题。任务完成后，问题仍需确认修复并验证，不能因任务状态改成完成就默认问题消失。

## 任务表字段

| 中文字段 | 记录内容 | 填写示例 | 用途 |
|---|---|---|---|
| 任务编号 | 每个任务的唯一编号 | T001 | 关联问题与风险；多表合并时不要重复 |
| 任务名称 | 一项明确、可交付的工作 | 完成交通感知需求梳理 | 识别任务 |
| 负责人 | 当前推进和反馈的人 | 杨乐楷 | 检查责任是否明确 |
| 截止日期 | 承诺完成的日期 | 2026-11-20 | 判断逾期、临近截止 |
| 状态 | 待开始、进行中、已完成 | 进行中 | 区分是否仍需跟进 |
| 最后更新 | 最近一次核实进展的日期 | 2026-11-10 | 判断长期未更新 |
| 验收标准 | 可观察、可验证的完成条件 | 核心场景测试通过并留存记录 | 避免“完成”口径不清 |
| 验证证据 | 测试报告、截图、评审结论的路径或链接 | docs/test-record.pdf | 已完成但无证据时预警 |
| 本周完成 | 本周实际完成的工作 | 完成需求清单评审 | 生成周报 |
| 下周计划 | 下一步可执行动作 | 组织原型评审并记录修改项 | 生成下周计划 |

## 问题表字段

| 中文字段 | 记录内容 | 填写示例 | 用途 |
|---|---|---|---|
| 问题编号 | 每个问题的唯一编号 | I001 | 区分和追踪问题 |
| 关联任务编号 | 问题所属任务编号 | T001 | 追溯问题影响哪个交付项 |
| 问题描述 | 可复现或明确的事实，不写笼统评价 | 数据时间戳格式不一致 | 理解偏差或缺陷 |
| 问题状态 | 待处理、处理中、待验证、已关闭 | 待验证 | 判断是否闭环 |
| 问题负责人 | 推动解决的人 | 张三 | 未闭环但无负责人时预警 |
| 验证结果 | 复测结论、证据或备注 | 复测通过，记录见某文件 | 支持关闭问题的依据 |

## 多文件怎么使用

例如分别上传“需求任务.xlsx”“研发任务.xlsx”“测试任务.xlsx”，工具会合并显示，保留来源文件。问题表也可同时上传多个。任务编号、问题编号应全局唯一；出现重复时页面提醒核对，不会静默覆盖或删除记录。

## 填写边界

不要为了展示而虚构负责人、进度、证据或验收结果。模拟数据必须标明用途；实际项目只使用获授权的脱敏信息。工具检查字段是否填写，不代表证据真实、验收一定通过。
