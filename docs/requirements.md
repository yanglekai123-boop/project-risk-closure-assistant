# 产品需求说明

## 目标用户

需要维护研发项目任务、问题与验收记录的项目助理、研发项目支持或交付实习生。

## 用户问题

任务表、问题记录与验证材料分散时，人工很难持续检查每个任务是否逾期、是否长期未更新、是否有人负责，以及“已完成”是否有证据。

## 产品目标

用轻量工具将分散记录转成可解释的风险清单和周报草稿，减少重复核查，不替代项目经理的优先级和资源决策。

## 最小版本范围

- 导入任务与问题CSV/Excel；
- 按固定规则扫描；
- 展示触发证据和建议动作；
- 导出风险清单与Markdown周报。

## 非目标

- 不自动调整计划、负责人或任务状态；
- 不判断上传证据的真实性；
- 不在第一版实现企业权限、多项目协同或第三方平台集成；
- 不让大模型参与风险判断、等级评定、优先级或紧急程度结论。

## AI 的能力边界

AI 只承担"非结构化文本 → 结构化字段"的录入工作，以及提示用户还缺哪些字段。实现上的三道约束：

1. 提示词禁止输出判断类字段；
2. `sanitize()` 白名单硬过滤，越权字段直接丢弃并提示；
3. 解析结果需人工确认才进入台账。

判断权始终在 `risk_rules.py` 的确定性规则。API Key 为空时自动降级为本地解析，保证离线可用。

## 产品评价方式

- 风险结果可追溯到具体字段；
- 同一输入与核查日期得到相同规则结果；
- 新用户可按模板独立上传并导出；
- 周报能明确区分事实、规则结果与建议。
